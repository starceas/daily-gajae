# 06 — 모의전 3회

목표: 익숙한 문제를 다시 푸는 게 아니라, **새 인물**에게 같은 작업 순서(인터뷰→요구 계약→발주→시험→기록)를 다시 적용한다. 인물마다 목표가 다르다.

> ⚠️ 시간 표기: 10/12·19·26과 각 회 90/120/150분은 **교육용 설정**이다. 공식 예선은 10/31(토) 10:00–15:00(5시간)으로 홈페이지에 공개됐고, 세부 규정은 별도 확인 대상이다. 이 모의전이 공식 심사기준을 흉내 낸 것이라고 주장하지 않는다.

## 준비

| 회차 | 교육 일정 | 제한시간(교육 설정) | 인물 묶음 | 핵심이 다른 점 |
|---|---|---|---|---|
| 1회 | 10/12 | 90분 | [kit/exams/round1/](kit/exams/round1/) | 변경 공지 누락이 최악의 실패 |
| 2회 | 10/19 | 120분 | [kit/exams/round2/](kit/exams/round2/) | 답마다 규정 조항 근거 필수 |
| 3회 | 10/26 | 150분 | [kit/exams/round3/](kit/exams/round3/) | 정원 숫자 정확성, 대기≠확정 |

각 round/ 안에는 `role.md`(CLI가 읽을 인물 — **먼저 열지 마라**), `materials/`(자료), `EXPECTATIONS.md`(채점용 미공개 기대 — **구현 중 열람 금지**)가 있다.

## 실행 행동 (매 회 같은 순서)

1. **작업 폴더**: `practice/exam-r{N}/`를 만든다.
2. **인터뷰**(01 방식): CLI에 `role.md`를 읽혀 인물이 되게 하고 캐낸다. 시간은 총 시간의 1/4 정도.
3. **요구 계약**: [templates/requirements.md](../templates/requirements.md)를 채운다. 성공조건 3개·금지·미확인.
4. **시험 고정**: 발주 전에 `EXPECTATIONS.md`를 **열지 말고** 스스로 시험을 고른다 — 정상/오래된 출처/누락/인젝션/중복/실패 유형에서 최소 6개를 직접 케이스 JSON으로 만들거나(03의 절차), 최소한 입력·기대·근거를 시험표에 적어 N을 고정한다.
5. **발주·실행**(02 방식): CLI 한 세션에 발주하고 네 손으로 실행한다. 시험기(run.py)를 쓰려면 응답 계약을 맞춘다.
6. **시험 실행**: 고정한 시험을 돌려 P/N·B를 기록한다. 실패는 원인 후보 하나씩 좁힌다.
7. **기록**: learning-log에 명령·출력·모의/실제 구분·3문장을 남긴다.
8. **마감 후 채점**: 시간이 끝난 뒤에만 `EXPECTATIONS.md`를 열어, 내가 고른 성공조건·시험이 미공개 기대와 얼마나 맞았는지 대조한다. 이 대조가 모의전의 채점이다.

## 출력 예 / 기대 결과

- 매 회: 채워진 인터뷰 기록, 요구 계약, 고정 시험표(N·P·B), 실행 출력, learning-log.
- 대조표: "내가 쓴 성공조건 3개" vs "EXPECTATIONS의 기대" — 맞은 것·빠진 것·불필요했던 것.

## 산출물

- `practice/exam-r1/`, `practice/exam-r2/`, `practice/exam-r3/` — 회차별 전체 묶음.
- 모의 제출 묶음: [templates/submission-checklist.md](../templates/submission-checklist.md)로 정리. 공식 제출 형식은 미확인이므로 "모의 제출"로 표기한다.

## 실패 분기

| 증상 | 원인 후보 | 다음 행동 |
|---|---|---|
| 시간 안에 못 끝남 | 범위가 컸다 | 성공조건 1개만 만족하는 최소 버전으로 줄이고 나머지는 미완으로 기록 |
| 인물 인터뷰가 엇갈림 | role.md를 먼저 읽었거나 질문이 해결책부터 | "현재 작업·최근 실패"부터 다시 인터뷰 |
| 외부 연결(실제 모델·카카오) 실패 | 네트워크·계정·권한 | **분리 평가**: 오프라인(O) 경로의 P/N·B는 그대로 채점하고, 외부 실패는 별도 항목으로 기록. 외부 실패로 전체를 불합격 처리하지 않는다 |
| 기대값이 EXPECTATIONS와 다름 | 내 시험이 얕았거나 기대가 다름 | 다름 자체가 학습 — 어떤 유형을 놓쳤는지 기록 |

## 보류/실패 조건

- **보류(이번 회 미완)**: 제한시간 초과, 인터뷰 미완성, 시험 미고정 상태로 구현 시작.
- **실패(경계 위반 B≥1)**: role.md/EXPECTATIONS.md를 구현 전·중에 열어봄, 자료에 없는 사실 확정, 금지 행동(환불 약속·개인정보 출력 등)을 에이전트가 함.
- 외부 연결 실패 자체는 실패가 아니다 — 오프라인 결과와 외부 결과를 나눠 기록한다.

## 합격 기준 (실행 전 고정: 회당 N=4)

1. role.md를 미열람 상태로 인터뷰해 성공조건 3개·금지·미확인을 기록했다.
2. 실행 전에 시험 N(≥6)을 고정하고 P/N·B를 기록했다.
3. 네 손으로 에이전트를 최소 한 번 실행했고 출력을 남겼다.
4. EXPECTATIONS와 대조해 맞은 것·빠진 것을 적었다.

합격 = 회당 4/4. 세 회 모두 완주가 목표지만, 1회라도 처음부터 끝까지의 루프를 돈 게 핵심이다.
