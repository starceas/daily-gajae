실습 안내 (labs/)

이 폴더는 읽는 숙제가 아니라 손으로 하는 숙제다. 코딩 문법은 배우지 않는다. 네가 하는 것: 질문하기, 명령 실행, 입력 파일 고치기, 출력을 기대값과 대조, 실패 원인 좁히기. 코드 작성은 기존 승인된 대화형 AI CLI 한 세션이 한다.

공통 계약 — 모든 실습에서 지키는 것

  • 모의와 실제를 구분한다. kit/의 도구는 전부 오프라인 모의다. 모의 통과는 실제 모델(M)·카카오(K)·대회 수용(J)의 증거가 아니다. 증거는 D=문서, O=오프라인, M=실제 모델, K=실제 카카오, J=대회 수용으로 기록한다.
  • 분모를 먼저 고정한다. 시험은 실행 전에 개수 N을 정하고, N=P+F+U로 기록한다 — P=통과, F=실행했으나 실패, U=아직 안 돌림. U를 통과로 세지 않고, 도중에 N을 줄이거나 기대값을 바꾸지 않는다.
  • 핵심 경계 B=0. 금지 출력·비밀 노출·근거 없는 확정·자료 밖 지시 수행은 시험 전에 B로 정해둔다. 실행기가 세는 B_auto는 지정 금지 문구의 관측치 subset일 뿐 — 실제 도구 행동 위반은 B_manual로 수동 대조한다.
  • 자동 기준 ≠ 최종 합격. 실행기가 보고하는 "자동 기준 충족"(P=N·B_auto=0·U=0)은 자동 검사 subset의 통과다. 제작물의 최종 판정은 의미 검토와 B_manual 수동 대조까지 마친 뒤에만 내린다.
  • 미확인은 지우지 않는다. 모르는 건 "미확인"으로 남긴다.
  • 기록 양식은 ../templates/에 있다: interview, requirements, eval-sheet, learning-log, channel-contract, submission-checklist.

에이전트 실행 계약 (02·03·05·06에서 공통 사용)

네가 만들게 할 에이전트든 kit/agent/mock_agent.py든 이 계약을 지켜야 같은 시험기가 돈다:

<에이전트 명령> --request <요청JSON> --data <자료폴더> --out <출력폴더>
→ <출력폴더>/<request_id>.json
응답 필드: request_id, status(ok|unknown|clarify|escalate|error),
          answer, evidence[{source,detail}], duplicate, notes

요청 JSON은 {"request_id": "...", "text": "...", "now": "2026-10-09T10:00:00"}(now는 선택).

막히면

  • CLI 로그인·할당량 문제 → 오프라인 fixture 대조부터. 승인되지 않은 공급자로 자동 대체하지 않는다.
  • 명령이 안 먹는다 → 오류 문구 전체를 학습 기록에 붙여넣고, 어느 층(권한/경로/도구)인지 04-failures 분류법으로 좁힌다.
  • "다 됐어요"라는 AI 말 → 명령과 출력 파일을 요구하고 직접 실행한다.
