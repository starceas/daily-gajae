AI를 지휘하는 사람의 엔지니어링 학습장

오늘은 가상 인물을 인터뷰하고, 그 사람이 성공했다고 말할 조건 3개를 적은 뒤, 작은 결과물 하나를 실행한다. 10월 과정의 목표는 혼자 요구를 찾고 → AI에 구현을 시키고 → 입력을 넣어 보고 → 실패 원인을 좁히는 것이다. 코딩 문법 공부는 하지 않는다.

이 자료는 개인 학습용이다. 공개 글이나 실서비스 수정을 숙제로 요구하지 않는다. 2026-10-01에 작성했으며 이후 링크·규정·제품 기능은 다시 확인해야 한다.

매일 자동 작성되는 블로그는 개념의 이름을 처음 만나는 곳으로 둔다. 여기서는 그 이름으로 상황을 설명하고 결정을 시험한다. 같은 날 멱등성을 읽었다면 중복 요청을 직접 넣어 보고, 왜 같은 답을 여러 번 보낼 수 있는지 설명하면 된다. 블로그를 읽었거나 용어를 외운 것만으로 실습 통과를 표시하지 않는다. 블로그와 이 과정은 자동으로 연동되지 않는다.

첫 90분

90분은 교육용 제안이다. 공식 홈페이지의 예선 안내는 10/31 10:00~15:00, 총 5시간이다. 중간에 멈춰도 기록을 남기고 이어간다. 준비는 Mac, 터미널, 이미 쓰는 대화형 AI CLI 하나, 이 폴더다. 새 계정·키·결제 없이 진행한다. 오프라인 모의 도구를 실행하려면 python3 --version이 나와야 한다. Python이 없으면 설치부터 하지 말고 실습의 파일·표 대조 경로를 택한다.

먼저 터미널에서 작업 폴더로 이동한다.

cd <학습 폴더>
시간 네가 직접 할 일 산출물과 기대 결과 막히면
0~10분 실습 안내를 읽고 기존 CLI 한 세션을 연다. 작업은 새 practice/first-agent/ 안으로 제한한다. 사용할 도구, 모의/실제 구분, 시험 N을 먼저 적는다. 로그인·할당량 문제면 오프라인 fixture 대조부터 한다. 승인 안 된 공급자로 바꾸지 않는다.
10~30분 인물 인터뷰를 수행한다. 해결책 제안보다 현재 작업과 실패 비용부터 묻는다. 질문·답변, 성공조건 3개, 미확인 항목. 말을 넓게 하면 “최근 실제 사례 하나”를 요청한다. 답이 없으면 가정으로 표시한다.
30~45분 요구 계약에 입력·출력·자료·금지 행동·실패 응답을 적는다. 한 문장 목표와 실제 입력/출력 예 1쌍. 기능이 많으면 성공조건 하나를 만족하는 최소 작업으로 줄인다.
45~70분 제작 실습의 발주를 한 CLI에 준다. AI가 만든 결과를 네가 실행하고 출력을 직접 읽는다. 실행 명령, 정상 출력, 모델을 사용했는지 여부. 먼저 준비된 오프라인 예제를 실행해 환경 문제와 구현 문제를 나눈다.
70~85분 평가 실습의 먼저 정한 시험을 돌린다. P/N, 실패한 입력, 수정 전후 출력. N을 줄이거나 기대값을 바꾸지 말고 원인 후보 하나를 시험한다.
85~90분 학습 기록에 “왜 실패했고 왜 이 수정이 맞나”를 3문장으로 남긴다. 행동·증거·설명. 모르면 “미확인, 다음에 볼 증거”로 남긴다.

첫 90분의 통과조건은 다음 4개를 모두 충족하는 것이다. 평가는 시작 전에 4개로 고정한다.

  1. 인물의 답변에서 나온 성공조건 3개와 미확인 항목을 기록했다.
  2. 입력/출력 예와 실패 응답을 적은 요구 계약을 만들었다.
  3. 최소 한 번 직접 실행하고 명령과 출력을 저장했다. 오프라인이면 모의로 표시했다.
  4. 고정 시험의 P/N과 핵심 경계 위반 B를 기록했다. 실패가 있으면 원인 후보와 다음 확인을 남겼다.

진입 과제 완료는 4/4다. 제작물 합격은 별도로 P=N, B=0, 미확인 명시가 필요하다. 90분 안에 제작물까지 합격하지 않아도 실패 증거가 있으면 다음 연습을 시작할 수 있다. 인터뷰 답의 양이나 AI가 생성한 코드 줄 수는 합격 기준이 아니다.

혼자 한다는 뜻

네가 목표·질문·자료 선택·완료조건·실행·수정 판단을 맡는다. 코드는 기존 대화형 AI CLI 한 세션이 만든다. Herdr의 워커 분할이나 다른 사람에게 결과물 전체를 넘기는 방식은 기본 실습에 쓰지 않는다.

AI가 “테스트 통과”라고 말하면 명령과 출력 파일을 요구하고 직접 실행한다. 결과가 좋지 않으면 “잘 고쳐”보다 실패 입력 하나, 기대 출력, 실제 출력, 먼저 볼 층을 준다. 구현 발주 양식을 복사해서 시작한다.

오프라인 도구는 원리를 재현하는 실험 장치다. 자료에서 정해진 규칙으로 답을 고르는 도구가 돌아간 것과 LLM이 실제 도구를 사용한 것은 다르다. 실제 모델 실습에서는 사용한 CLI·모델·입력·도구 실행·응답을 실행 기록에 남긴다. 코드를 만든 AI와 만들어진 프로그램도 구별한다.

숙련은 이렇게 판정한다

수준 할 수 있어야 하는 행동 증거
요구를 찾는다 해결책을 정하기 전 목표·예외·비용을 묻고 모르는 것을 남긴다. 인터뷰 기록과 요구 계약
작게 만든다 한 입력이 자료/도구를 거쳐 검증된 응답으로 나오는 경로를 혼자 엮는다. 재현 명령과 출력
고친다 실패를 모델·도구·네트워크·상태·권한 중 어디서 발생했는지 좁힌다. 실패 입력, 가설, 판별 시험, 전후 출력
평가한다 기대값과 시험 N을 실행 전에 고정하고 개발용과 확인용을 나눈다. P/N, 핵심 위반 B, 시험 변경 이력
운영을 설명한다 중복·재시작·응답 상실·설정 덮어쓰기 때 결과가 왜 달라지는지 예측한다. 사건 순서, 상태 기록, 반례

매 연습 후 AI를 닫고 3문장으로 답해 본다. “무엇이 일어났나 / 왜 그렇게 됐나 / 어떤 증거가 있으면 내 설명이 틀리나.” 답이 막히면 해당 원리 단원으로 돌아간다. 수식을 외울 필요는 없지만 분모와 사건 순서는 고정해야 한다.

10월 대회 준비의 경계

공식 홈페이지에서 AI_TOP_100 2026 온라인 예선 10/31 10:00~15:00, 총 5시간, 개인전, 가상 인물 인터뷰 후 AI 에이전트 제작·제출, AI 도구 별도 제한 없음을 확인했다. 참가를 위한 카카오 계정 로그인·카카오톡 계정 연동은 필수다. 제작할 에이전트의 카카오 연결 방식·기술 제출 형식·상세 부정행위 규정은 미확인이다. 상세 규정은 참가자 메일·예선 사이트에서 재확인한다. 공식 홈페이지, 조사 판정

공식 홈페이지 상단에는 접수 마감, 하단에는 10/21 18:00 예정 마감이 함께 표시된다. 개인의 접수 여부는 확인하지 않았다. 이미 받은 접수 확인 메일·알림톡과 참가자 안내를 직접 확인해야 한다. 날짜 표시만 보고 접수 가능하다고 추정하지 않는다.

카카오 로그인, 나에게 메시지 보내기, 친구에게 보내기, 채널 챗봇 스킬, 비공식 개인계정 자동화는 서로 다른 경로다. 한 경로의 성공을 다른 경로의 증거로 쓰지 않는다. 연결 계약을 먼저 채운다. 기본 실습은 로컬 카카오 요청 fixture와 응답 대조까지다. 이는 연결 원리를 배우는 선택 실습이며, 공식 제작물 연결 방식을 예측한 것이 아니다. 네이티브 연결은 계정·권한·서버 주소·응답시간·실제 왕복 증거를 별도로 확인한다.

10/12·19·26 모의전은 학습 일정 제안이다. 공식 심사기준을 흉내 냈다고 주장하지 않는다. 목표는 새로운 인물의 요구를 기존 답에 끼워 맞추지 않고, 같은 작업 순서로 다시 푸는 것이다.

멈췄다가 이어갈 때

학습 기록의 다음 입력 한 줄부터 실행한다. 이전 출력은 실행 당시의 증거로 두고, 새 실행 결과로 덮어쓰지 않는다. 참고 초안 ref/와 기존 하네스·봇 설정은 학습 중 수정하지 않는다. 새 학습 폴더에서 문제를 재현한다.
