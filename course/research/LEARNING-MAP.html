2. 고정 분모로 닫는 학습 평가

교재 작성자가 실행 전에 버전과 시험 ID를 고정한다. 한 시험의 통과는 그 시험에 적힌 모든 필수 조건이 관측됐을 때만 인정한다.

N = 사전 고정 필수 시험 수 > 0

P = 통과 시험 수, F = 실패 시험 수, U = 미실행·판정 불가 시험 수

N = P + F + U, 관측 통과율 = P / N

과제 통과 = (P = N) ∧ (B = 0) ∧ (미확인 항목을 명시함)

B는 핵심 경계 위반 횟수다. 외부 송신, 금지된 모델 호출, 근거 없는 실제 연결 성공 표기 등을 포함한다. N=0이면 판정 불가이고, 미실행 항목을 빼서 분모를 줄일 수 없다. 이 식은 해당 시험판의 관측 결과만 판정한다. 임의의 미래 입력에도 성공한다는 확률 보증이 아니다.

작성자가 준비할 최소 사례군은 다음과 같다. 아래는 대회 숨은 채점 기준이 아니라 교육용 예시다.

사례군 기대 행동 확인할 증거
정상 요구 필요한 자료를 읽고 출처를 붙여 답함 사용한 자료 ID·답변·실행 기록
요구 누락 부족한 정보를 질문하고 행동을 보류 추가 질문과 보류 상태
출처 없음/상충 확정하지 않고 미확인 또는 상충 이유를 표시 주장과 출처의 대응표
같은 요청 재입력 같은 요청 ID의 효과가 중복되지 않음 요청 ID별 모의 효과 건수

수정용과 확인용 시험은 별도 묶음으로 둔다. 확인용 답을 보고 고친 뒤 같은 시험을 다시 통과했다면 수정용 결과로 기록하고, 새 확인용 시험을 준비한다. 혼자 학습할 때 답안을 뒤에 두는 것은 편의상 분리일 뿐 강제된 비공개가 아니다. 독립 평가자는 작성·수정에 관여하지 않은 세션으로 둔다.

오프라인 장치의 출력은 fixture/모의 실행으로 표시한다. 실제 모델을 부르지 않는 장치를 LLM 추론으로 표현하지 않는다. 이후 실제 모델을 쓰는 과제가 승인되면 모델 입력·도구 선택·결과를 별도 증거로 남겨야 한다. 카카오·대회 수용 증거도 따로 필요하다.

3.1 DB·Git·macOS 권한·인증 단원 보완

추가로 직접 읽은 자료는 아래 여섯 개뿐이다. course/03-next.md는 이번 보완 요청 직후 읽기를 시도한 시점에는 아직 없었다. 따라서 이 표는 해당 파일 작성자가 옮겨 쓸 첫 과제이며, 완성 단원과 대조했다는 뜻은 아니다.

각 행은 원문에서 지정한 부분을 먼저 읽고 수행한다. 아래 수치·역할·상태는 교육용 가상 값이다. DB 설치·Git 저장소 변경·Mac 설정 변경·실제 로그인은 필요하지 않다.

주제·자료와 읽을 부분 첫 행동 산출물·완료조건
DB 트랜잭션: S04 — PostgreSQL §3.4, 첫 설명과 BEGIN/COMMIT/ROLLBACK 문단. SQL은 건너뛰어도 됨 계정 A=100, B=50에서 20을 옮기는 가상 장부를 만든다. 두 변경 모두 확정, 중간 실패 후 취소, 일부만 저장의 세 경우를 계산 결과가 각각 (80,70), (100,50), (80,50). 앞의 둘은 합 150, 부분 저장은 130임을 도출. DB 밖의 메시지 발송도 함께 취소된다고 주장하지 않음
DB 인덱스: S05 — PostgreSQL §11.1, 책 색인 비유·사용 선택·마지막 유지 비용 설명 ID가 섞인 자료 카드 8행을 만든다. 8행 전체를 읽는 방법과 ID→행 위치 색인으로 찾는 방법으로 같은 ID를 찾는다. 새 행 추가 때 색인에서 바꿀 항목을 표시 두 방법의 결과 행 일치, 조사한 항목 수와 색인 유지 작업을 각각 기록. 이것을 실제 DB 응답시간 측정이나 ‘항상 색인이 빠름’으로 일반화하지 않음
Git 내부: S06 — Pro Git의 blob 설명·Tree Objects·Commit Objects 파일 내용 카드, 파일명→내용 카드, 부모·트리·설명 카드로 두 버전의 가상 이력을 그린다. 두 번째 버전에서 파일 하나만 바꾸고 첫 버전으로 향하는 참조를 따라간다 blob/tree/commit의 역할을 구별하고 두 시점의 내용 복원. 명령 실행 없이 카드 관계로 증명하며, 원격 저장·push·배포를 했다고 표시하지 않음
macOS 앱 권한: S07 — Apple의 Files & Folders 설명 같은 문서 위치에 앱 A는 거부, 앱 B는 허용이라는 가상 표를 만들고 필요한 접근을 비교한다. 공식 문서에 나온 확인 위치만 메모한다 요청 앱·대상 위치·허용 여부·근거의 네 칸 완성. 실제 상태는 미확인으로 유지. 접근 실패를 모델 오류로 확정하거나 모든 권한을 켜는 처방을 하지 않음
인증: S08 — OWASP Authentication의 Introduction·Authentication Responses 인증 성공, 잘못된 증명, 없는 계정, 잠긴 계정의 가상 결과 네 개에 사용자 응답을 적는다. 내부 원인 분류와 외부 오류 문구를 분리한다 성공과 실패를 구별하되 실패 문구만으로 계정 존재를 알아낼 수 없게 작성. 신원 확인이 개별 작업 허용까지 뜻하지 않음을 설명. 실제 비밀번호·토큰을 기록하지 않음
인가·최소권한: S09 — OWASP Authorization의 Least Privileges·Deny by Default·Every Request 조회 전용 역할과 변경 담당 역할, 가상 자료 A·B에 대해 읽기·수정·발송의 권한표를 만든다. 각 허용 칸에 필요 이유를 적고 미지정 요청을 넣는다 필요한 허용만 표시하고 나머지는 거부. ‘인증 성공+권한 없음’과 ‘이전 요청 허용+다음 요청 권한 없음’ 두 반례를 모두 거부. 실제 계정 설정은 변경하지 않음

각 행의 결과는 개념·모의 과제 증거다. 실제 PostgreSQL 동작, 저장소 복구, Mac 접근 허용, 인증·권한 통제가 검증됐다는 증거와 분리한다.
